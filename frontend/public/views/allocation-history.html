Notes

  1. The subject is typed position_actions, so the aggregator's meanTakeWeights() never runs for it and a session publishes a rationale and a set of actions instead of a weight vector. The column renders a vector the day the subject is retyped; it does not invent one meanwhile.
  2. NAV per share and true period returns need a route over vault_share_price_history. One number is not a series, so the vault's spot share price is not stretched into one.
  3. The signed consensus receipt is a separate artifact from the session page linked in each row. Its public route returns an error for every published session today, so this page does not request it and does not link to it. The session page is the readable record until that is fixed.
  4. A recommendation is not binding. Applying one to the target weights is gated by the admin multisig and there is no code path that writes it, which is why every row here reads "unchanged".
